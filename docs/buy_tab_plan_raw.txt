# iMaliChat Buy Tab -- Complete Phased Implementation Plan

## Preface: What Exists Today

The Buy Tab is the 5th tab in the app's bottom navigation. It has working plumbing at every layer but the main screen shows a placeholder image. Here is a precise inventory:

**Flutter Domain Layer:**
- `lib/domain/entities/purchase.dart` -- `Purchase` entity (Freezed) with `PurchaseCategory` enum (airtime, data, electricity, voucher, other) and `PurchaseStatus` enum (pending, processing, completed, failed, refunded)
- `lib/domain/entities/service_provider.dart` -- `ServiceProvider` entity (Freezed) with embedded `ServiceProduct` value object (id, name, code, priceTokens, priceZar, validity, etc.)
- `lib/domain/repositories/purchase_repository.dart` -- Abstract interface with methods: `getServiceProviders`, `getProvidersByCategory`, `getProviderById`, `getProducts`, `getProductById`, `makePurchase`, `getPurchaseHistory`, `getPurchaseById`, `getRecentRecipients`, `validateRecipientNumber`

**Flutter Data Layer:**
- `lib/data/models/purchase_model.dart` -- Freezed model with manual `fromJson` (handles Timestamp), `toFirestoreJson`, `toEntity`, `fromEntity`. Note: models embed conversion methods directly; there are no separate mapper classes.
- `lib/data/models/service_provider_model.dart` -- Same pattern, includes `ServiceProductModel`
- `lib/data/datasources/remote/purchase_remote_datasource.dart` -- Reads from Firestore collections `serviceProviders`, `serviceProducts`, `purchases`. Calls `processPurchase` Cloud Function for VAS purchases. Uses `PlayIntegrityService` for security.
- `lib/data/repositories/purchase_repository_impl.dart` -- `@LazySingleton(as: PurchaseRepository)` implementation

**Flutter Presentation Layer:**
- `lib/presentation/blocs/purchase/purchase_bloc.dart` -- `@injectable` BLoC with 14 event handlers covering the full VAS purchase lifecycle
- `lib/presentation/blocs/purchase/purchase_event.dart` -- 13 Freezed events (loadProviders, loadProvidersByCategory, selectCategory, selectProvider, loadProducts, selectProduct, setRecipientNumber, validateRecipient, makePurchase, loadHistory, loadRecentRecipients, selectRecentRecipient, resetSelection, clearError, clearSuccess)
- `lib/presentation/blocs/purchase/purchase_state.dart` -- Freezed state with fields for loading states, providers list, products list, history, selection, recipient validation, purchase status
- `lib/presentation/screens/buy/buy_services_screen.dart` -- Shows `dragons.jpg`; the full VAS UI is in commented-out `_buildOriginal` method (category chips, provider grid, product list, recipient input)
- `lib/presentation/screens/buy/buy_wallet_selection_screen.dart` -- Working wallet/sub-account selector with purchase confirmation
- `lib/presentation/screens/buy/buy_success_screen.dart` -- Full success screen with voucher code display and clipboard copy
- `lib/presentation/screens/buy/buy_failure_screen.dart` -- Full failure screen with retry flow
- `lib/presentation/screens/buy/buy_transactions_screen.dart` -- Placeholder "Coming Soon"

**Router** (`lib/presentation/router/app_router.dart`):
```
/buy (BuyServicesScreen)
  /buy/wallet-selection (BuyWalletSelectionScreen)
    /buy/wallet-selection/success (BuySuccessScreen)
    /buy/wallet-selection/failure (BuyFailureScreen)
  /buy/transactions (BuyTransactionsScreen)
```

**Cloud Functions:**
- `functions/src/purchases.ts` -- `processPurchase` (onCall) and `getPurchaseDetails` (onCall). `processPurchase` validates balance (main wallet or sub-account), creates purchase doc, calls `processPurchaseTransaction` from the ledger, simulates VAS provider API, handles failure reversal with `reverseJournal`.
- Exported in `functions/src/index.ts` via `export * from "./purchases"`

**Ledger System:**
- `functions/src/ledger/index.ts` -- `processPurchaseTransaction(userId, providerId, providerName, amount, purchaseId, subAccountId?, accountTypeId?, metadata?)` creates a double-entry journal: debit user account, credit supplier account. Uses `createTransferEntries`, `postJournal`, `debitSubAccount` inside a Firestore transaction.
- `functions/src/ledger/types.ts` -- JournalType includes `"purchase"`, IdempotencyKey has `purchase(purchaseId)`, AccountId has `supplier(providerId)`, SystemAccounts has gift/spray escrow accounts as reference pattern
- `functions/src/ledger/giftSprayEscrow.ts` -- `processGiftDebit`, `processGiftCredit`, `processGiftRefund` provide the exact pattern to follow for marketplace escrow (debit user -> credit escrow; debit escrow -> credit recipient/refund)

**BLoC Provision Pattern** (`lib/app.dart`):
- All BLoCs are resolved from GetIt in `initState()`: `_purchaseBloc = getIt<PurchaseBloc>()`
- Provided via `MultiBlocProvider` with `BlocProvider<PurchaseBloc>.value(value: _purchaseBloc)`

**Key Convention Notes:**
- Entities use `@freezed`, NOT Equatable
- Models use `@freezed` with manual `fromJson`/`toFirestoreJson` (NOT `@JsonSerializable` in practice)
- Conversion is `toEntity()` / `fromEntity()` on the model class itself, not separate mapper files
- BLoCs use `@injectable`, NOT Cubits
- All navigation uses GoRouter, never `Navigator.push()`
- DI: `@LazySingleton(as: RepositoryInterface)` for repos, `@LazySingleton(as: DatasourceInterface)` for datasources
- Firestore write collections are locked (`allow write: if false`) and managed exclusively via Cloud Functions
- Consumer-facing Cloud Functions use `onCall` with `requireAppCheck` and `requirePlayIntegrity`

```dart
@override
Future<List<BuyCategoryModel>> getBuyCategories() async {
  final snapshot = await _firestore.collection('buyCategories')
      .where('isActive', isEqualTo: true)
      .orderBy('sortOrder')
      .get();
  return snapshot.docs.map((doc) {
    final data = doc.data();

    return BuyCategoryModel.fromJson(sanitizeFirestoreData(data));
```

```dart
Future<void> _onLoadBuyCategories(
  _LoadBuyCategories event,
  Emitter<PurchaseState> emit,
) async {
  emit(state.copyWith(isLoadingCategories: true));
  final result = await _purchaseRepository.getBuyCategories();
  result.fold(
    (failure) => emit(state.copyWith(
      isLoadingCategories: false,
      errorMessage: failure.displayMessage,
    )),
    (categories) => emit(state.copyWith(
      isLoadingCategories: false,
      buyCategories: categories,
    )),
  );
}
```

```typescript
export const onPurchaseCompleted = onDocumentUpdated(
  { document: "purchases/{purchaseId}", region: "africa-south1", labels: { area: "wallet" } },
  async (event) => {
    const before = event.data?.before.data();
    const after = event.data?.after.data();
    if (!before || !after) return;

    // Only process status transitions to "completed"
    if (before.status === "completed" || after.status !== "completed") return;

    const userId = after.userId;
    const deduplicationKey = `${after.productId}_${after.recipientNumber}`;

    const regularsRef = db.collection("users").doc(userId).collection("buyRegulars");

    // Check for existing regular with same product + recipient
    const existing = await regularsRef
      .where("productId", "isEqualTo", after.productId)
      .where("recipientNumber", "isEqualTo", after.recipientNumber)
      .limit(1)
      .get();

    if (!existing.empty) {
      // Update usage count and lastUsedAt
      await existing.docs[0].ref.update({
        usageCount: admin.firestore.FieldValue.increment(1),
        lastUsedAt: admin.firestore.FieldValue.serverTimestamp(),
        priceTokens: after.tokenAmount,
        priceZar: after.zarAmount,
      });
    } else {
      // Create new regular
      await regularsRef.add({
        providerId: after.providerId,
        providerName: after.providerName,
        productId: after.productId,
        productName: after.productName,
        productCode: after.productCode,
        recipientNumber: after.recipientNumber,
        category: after.category,
        priceTokens: after.tokenAmount,
        priceZar: after.zarAmount,
        providerLogoUrl: null,
        isPinned: false,
        usageCount: 1,
        lastUsedAt: admin.firestore.FieldValue.serverTimestamp(),
        createdAt: admin.firestore.FieldValue.serverTimestamp(),
      });
    }
  }
);
```

```typescript
export const onVouchCreated = onDocumentCreated(
  { document: "vouches/{vouchId}", region: "africa-south1", labels: { area: "marketplace" } },
  async (event) => {
    const vouch = event.data?.data();
    if (!vouch) return;

    const providerId = vouch.providerId;

    // Aggregate all vouches for this provider
    const vouchesSnap = await db.collection("vouches")
      .where("providerId", "==", providerId)
      .get();

    const totalVouches = vouchesSnap.size;
    const avgRating = vouchesSnap.docs.reduce((sum, doc) => sum + (doc.data().rating || 0), 0) / totalVouches;

    // Trust score = weighted average: 60% vouch rating + 40% order completion rate
    const providerDoc = await db.collection("providers").doc(providerId).get();
    const completedOrders = providerDoc.data()?.completedOrders || 0;
    const orderFactor = Math.min(completedOrders / 10, 1.0); // cap at 10 orders
    const trustScore = (avgRating * 0.6) + (orderFactor * 5 * 0.4);

    await db.collection("providers").doc(providerId).update({
      trustScore: Math.round(trustScore * 100) / 100,
      vouchCount: totalVouches,
      averageRating: Math.round(avgRating * 100) / 100,
      totalRatings: totalVouches,
    });
  }
);
```

**New File:** `functions/src/ledger/marketplaceEscrow.ts`

Follows the exact pattern of `functions/src/ledger/giftSprayEscrow.ts`:

```typescript
import { SystemAccounts, AccountId, IdempotencyKey } from "./types";
import { postJournal } from "./journals";
import { ensureSystemAccounts, getOrCreateUserAccount } from "./accounts";
import { debitSubAccount } from "./subAccounts";
import * as admin from "firebase-admin";

const db = admin.firestore();

/**
 * Escrow buyer tokens for marketplace purchase.
 * Debit buyer, credit MARKETPLACE_ESCROW.
 */
export async function processMarketplaceEscrow(
  buyerId: string,
  amount: number,
  orderId: string,
  subAccountId?: string,
  description?: string
): Promise<string> {
  await Promise.all([ensureSystemAccounts(), getOrCreateUserAccount(buyerId)]);

  const buyerAccountId = AccountId.user(buyerId);
  const escrowAccountId = SystemAccounts.MARKETPLACE_ESCROW;

  const result = await db.runTransaction(async (tx) => {
    const journalResult = await postJournal({
      idempotencyKey: IdempotencyKey.marketplaceEscrow(orderId),
      type: "marketplace_escrow",
      description: description || `Marketplace escrow for order ${orderId}`,
      entries: [
        { accountId: buyerAccountId, entryType: "debit", amount },
        { accountId: escrowAccountId, entryType: "credit", amount },
      ],
      referenceType: "marketplace_order",
      referenceId: orderId,
      initiatedBy: buyerId,
      subAccountId: subAccountId || null,
    }, tx);

    if (journalResult.success && !journalResult.isDuplicate && subAccountId) {
      await debitSubAccount(buyerId, subAccountId, amount, tx);
    }

    return journalResult;
  });

  if (!result.success) {
    throw new Error(result.error || "Failed to escrow marketplace tokens");
  }
  return result.journalId!;
}

/**
 * Release escrowed tokens to seller.
 * Debit MARKETPLACE_ESCROW, credit seller.
 */
export async function releaseMarketplaceEscrow(
  sellerId: string,
  amount: number,
  orderId: string,
  description?: string
): Promise<string> {
  await Promise.all([ensureSystemAccounts(), getOrCreateUserAccount(sellerId)]);

  const sellerAccountId = AccountId.user(sellerId);
  const escrowAccountId = SystemAccounts.MARKETPLACE_ESCROW;

  const result = await postJournal({
    idempotencyKey: IdempotencyKey.marketplaceRelease(orderId),
    type: "marketplace_release",
    description: description || `Marketplace release for order ${orderId}`,
    entries: [
      { accountId: escrowAccountId, entryType: "debit", amount },
      { accountId: sellerAccountId, entryType: "credit", amount },
    ],
    referenceType: "marketplace_order",
    referenceId: orderId,
    initiatedBy: "system",
  });

  if (!result.success) {
    throw new Error(result.error || "Failed to release marketplace escrow");
  }
  return result.journalId!;
}

/**
 * Refund escrowed tokens to buyer.
 * Debit MARKETPLACE_ESCROW, credit buyer.
 */
export async function refundMarketplaceEscrow(
  buyerId: string,
  amount: number,
  orderId: string,
  subAccountId?: string,
  description?: string
): Promise<string> {
  await Promise.all([ensureSystemAccounts(), getOrCreateUserAccount(buyerId)]);

  const buyerAccountId = AccountId.user(buyerId);
  const escrowAccountId = SystemAccounts.MARKETPLACE_ESCROW;

  const result = await postJournal({
    idempotencyKey: IdempotencyKey.marketplaceRefund(orderId),
    type: "marketplace_refund",
    description: description || `Marketplace refund for order ${orderId}`,
    entries: [
      { accountId: escrowAccountId, entryType: "debit", amount },
      { accountId: buyerAccountId, entryType: "credit", amount },
    ],
    referenceType: "marketplace_order",
    referenceId: orderId,
    initiatedBy: "system",
    subAccountId: subAccountId || null,
  });

  if (!result.success) {
    throw new Error(result.error || "Failed to refund marketplace escrow");
  }
  return result.journalId!;
}
```

## Key Architectural Decisions Summary

1. **BLoCs, not Cubits.** All state management uses `Bloc<Event, State>` with `@freezed` events and states. The spec's Cubit proposals are adapted to BLoCs.
2. **Existing directory structure, not `features/buy/`.** Domain entities go in `lib/domain/entities/`, models in `lib/data/models/`, etc.
3. **Extend PurchaseBloc for VAS, new BLoCs for marketplace.** The existing `PurchaseBloc` handles VAS purchases (Phase 1-2). `MarketplaceBloc`, `OrderBloc`, and `GroupBuyBloc` handle marketplace and group buy concerns (Phases 3-4).
4. **Models embed conversion, no separate mapper classes.** Following the pattern in `PurchaseModel.toEntity()` / `PurchaseModel.fromEntity()`.
5. **Marketplace Cloud Functions in `functions/src/marketplace.ts`.** This is a consumer-facing file, not an admin file. The CLAUDE.md rule about not creating new top-level files applies only to admin functions.
6. **Escrow follows the gift/spray escrow pattern.** `processMarketplaceEscrow` / `releaseMarketplaceEscrow` / `refundMarketplaceEscrow` mirror `processGiftDebit` / `processGiftCredit` / `processGiftRefund` in `functions/src/ledger/giftSprayEscrow.ts`.
7. **Feature flags are Firestore-backed, not Firebase Remote Config.** Per spec requirement, with 30-min client cache.
8. **`PurchaseCategory` is NOT extended.** The grid display uses a separate `BuyCategory` entity backed by Firestore, decoupling the display taxonomy from the VAS transaction enum.
9. **Firestore collections are write-locked.** All writes go through Cloud Functions. Client code only reads.
10. **Each phase is independently deployable and testable.** Phase 1 activates the Buy Tab with VAS. Phase 2 adds UX convenience. Phase 3 is the marketplace. Phase 4 is group buying. No phase depends on a subsequent phase.
